2026-11-03 · v0.2.1(10/30)에 화면 55개를 끝까지 그리며 정한 규격을 모두 반영한 최종본 · 11/04 갱신(랜딩 컴포넌트 · 운영자 1:1 문의)

| 항목 | 내용 |
|---|---|
| 버전 | **v0.2.1 최종본** — 개발 기준판. 화면과 이 문서가 다르면 화면(캔버스 보드)이 맞고, 이 문서를 고친다 |
| 기준 화면 | 화면 설계 캔버스 보드 60개 중 사용 56개(비로그인 · 공통 10 · 의뢰인 22 · 공급자 17 · 운영자 7) |
| 공용 스타일 | `mj.css` — 토큰과 공용 컴포넌트. 화면별 스타일은 각 보드 안. **코드로 옮길 토큰은 14절** |
| 연계 문서 | PRD v0.7 최종본 · ERD v0.7 최종본 · 프론트엔드 개발 준비(화면 목록 · 경로 · 상태 · 공통 컴포넌트) |

### 이 판을 읽는 법

- **1~9절 시각 규칙** — 색 · 글자 · 간격 · 컴포넌트 모양. 서비스가 바뀌어도 그대로 쓴다
- **10절 서비스 매핑** — "이 상태는 이 칩", "이 금액은 누구에게" 같은 연결표. 정책이 바뀌면 이 절만 고친다
- **14절 코드 토큰** — 프론트엔드가 그대로 옮길 CSS 변수

새 상태나 화면이 생기면 10절에 줄을 더하고, 모양은 1~9절의 컴포넌트에서 고른다. **새 모양을 만들기 전에 기존 컴포넌트로 표현할 수 없는지 먼저 본다.**

### 원칙

1. **신뢰는 색이 아니라 구조가 만든다.** 금액 근거, 열람 기록, 예치 상태, 중개자 지위 고지가 파란색보다 먼저다.
2. **플랫폼은 완성돼 보이고, 초안은 미완성으로 보인다.** 두 계층을 분리한다(2절).
3. **색은 상태를 말하고, 라벨이 그것을 확인한다.** 색만으로 구분되는 정보를 만들지 않는다.
4. **화면은 판정하지 않는다.** 금액 · 공급자를 나란히 보여주되 "최저가", "비쌈", "추천" 같은 판정 표시를 붙이지 않는다. 운영자 화면도 근거만 보이고 판단은 운영자가 한다.
5. **(최종본 추가) 경고는 빨강이 아니라 amber다.** 지금 해야 할 일 · 기한 · 위험 행동은 모두 amber로 말한다. 빨강은 폼 입력 오류와 알림 점에만 남긴다.

## 2. 2계층 규칙

| 계층 | 범위 | 색 |
|---|---|---|
| 플랫폼 크롬 | GNB, 버튼, 명세, 금액, 칩, 대화 | 1절 전체 |
| 초안 캔버스 | 2분할 왼쪽의 화면 초안, 명세 · 상세 화면의 초안 썸네일 | **슬레이트만. 브랜드 · 상태 색 금지** |

- 블록은 점선 외곽선(slate-400) + 흰 바탕, 블록 이름 14/600 slate-600, 삭제 ×도 slate
- 블록 안은 와이어프레임으로 그린다 — 부품 6종(달력 · 입력 폼 · 목록 · 버튼 · 텍스트 · 미리 보기). 선택된 날짜 · 세그먼트는 slate-200 바탕
- 만드는 중인 블록은 점선 slate-300 자리 + 중립 칩 '만드는 중'
- 캔버스 안에 실제 상호를 넣지 않는다 — '가게 이름'으로 둔다

## 3. 공간 분리 · GNB · 운영자 셸

### 공간 극성

| 공간 | 상단 | 본문 | 푸터 |
|---|---|---|---|
| 비로그인(랜딩 · 가입 · 약관 · 재설정 · 고객센터) | 흰 헤더 + slate-200 하단선. 공급자 랜딩은 navy-900 | slate-50 + 흰 카드 | 있음 |
| 의뢰인 | 흰 GNB + slate-200 하단선 | slate-50 + 흰 카드 | 있음 |
| 공급자 | **navy-900 GNB**, 하단선 없음 | slate-50 + 흰 카드 | 있음 |
| 운영자 | 흰 상단 바(64) + **navy-900 사이드 메뉴** | slate-50, 표 · 목록 + 상세 중심 | **없음** |

공통 화면(계약서 · 채팅 · 정산 등)은 **보는 사람의 공간 GNB**를 쓴다. 의뢰인 · 공급자 보드로 나눠 그렸고, 본문 구조는 같다.

### 메뉴 (공간마다 고정, 모든 화면 동일)

| 공간 | 메뉴 | 오른쪽 |
|---|---|---|
| 의뢰인 | 홈 · 프로젝트 시작 · 내 프로젝트 · 내 계약 · 정산 내역 | 채팅 · 알림 · 계정 |
| 공급자 | 홈 · 프로젝트 찾기 · 내 지원 · 내 계약 · 북마크 | 채팅 · 알림 · 계정 |
| 의뢰인 랜딩 | 작동 방식 · 안전장치 · 비용(페이지 안 이동) | 토글 · 로그인 · '화면 초안 받아보기'(작은 기본 버튼 → 회원가입) |
| 공급자 랜딩 | 견적 방식 · 이용 흐름 · 정산 · 비용(페이지 안 이동) | 토글 · 로그인 · 가입 CTA |
| 고객센터(비로그인) | 의뢰인 안내 · 공급자 안내 · 고객센터 | 로그인 · 회원가입 |

- 화면의 주 행동 버튼을 GNB에 넣지 않는다. 페이지 머리나 하단 바에 둔다
- GNB에 있는 메뉴와 같은 버튼을 본문 인사줄에 다시 두지 않는다
- **로그인은 모달**이다. 열어도 뒤 페이지의 헤더는 그대로 보인다
- 공급자 GNB에는 '정산 내역' 메뉴가 없다 — 내 계약의 '정산 내역 보기'로 들어간다

## 8. 금액 표기

- **모든 금액에 '원'**, 부가세 포함, 오른쪽 정렬 + tabular-nums. 범위를 짧게 쓰는 속성 표기만 '만원'
- AI 금액은 'AI 예상 · 참고용' 태그 + '약 N원', 색은 slate-900(navy 아님)
- 금액이 없는 항목은 합계에서 빼고 합계 아래 '+ 금액 미정 N건'(13 slate-600)
- 바뀐 금액: 새 금액 아래 amber 한 줄 '채팅에서 수정 · 처음 N원'
- 할 수 없는 항목: '불가' amber-700 글자. 칩을 쓰지 않는다
- 합계 블록: navy-900 radius 12 — 항목 줄 15 on-navy-sub + 흰 값 → on-navy-line 선 → 총액 28/600 흰색
- 예산 초과는 amber 문구. 레드를 쓰지 않는다
- 내역 줄: '구간 금액 1,550,000원 − 수수료 77,500원 − 원천징수 51,150원 = 1,421,350원'(13 slate-600), 받을 금액만 16/600
- 역할별 '내 금액': 의뢰인은 **예치할 금액**(합의 + 수수료), 공급자는 **받을 금액**(합의 − 수수료(− 원천징수))

| 비교 행렬 | **제안 비교에 쓰지 않는다.** 공급자 카드(속성 표기 + '질문 N' 칩 + 틴트 '문의하기 (채팅)', 파란 버튼 없음). 규격은 다른 비교용으로 남긴다 |

| 공개 범위 구획 | '전체 공개' / '상세 공개(열람 기록)' 두 카드. 의뢰인 프로필은 상세 공개 카드 안 |
| 공간 토글 | 비로그인 랜딩에만 |
| 알림 목록 페이지 | 폐기 → 알림 드롭다운 |
| 선택 카드의 2지선다(확인 질문) | 폐기. 선택 카드는 사유 · 유형 · 구분 선택에 쓴다 |

## 11. 접근성

- WCAG AA(본문 4.5:1, 큰 글자 3:1). 가장 연한 글자는 slate-500
- 색 단독 의존 금지 — 상태는 색 + 라벨, 금액 변경은 색 + 문구, 불가는 색 + 글자, 안 읽음은 점 + 굵기 + 바탕
- 포커스 링은 항상 보이게(blue-600 2px, blue-50 위에서는 navy-900 2px)
- blue-50 위 글자는 navy-900. 네이비 위에 blue-600 글자 금지
- 비활성은 이유 문구와 함께
- 모달 · 드롭다운은 Esc로 닫히고 포커스가 돌아간다. 대화 영역은 목록 구조
- 키보드로 탭 · 세그먼트 · 선택 카드 · 별점을 고를 수 있다

## 12. 금지 사항

- 화면 초안 캔버스에 브랜드 · 상태 색을 쓰지 않는다
- 한 화면에 파란 버튼을 둘 이상 두지 않는다. 목록 · 카드 행동은 틴트
- **빨강을 폼 오류 · 미확인 점 밖에서 쓰지 않는다.** 예산 초과 · 거절 · 불가 · 취소 · 마감 · 결제 실패 · 위험 행동은 amber 또는 아웃라인
- 위험 행동 모달에 파란 버튼을 두지 않는다
- 금액이나 공급자에 '최저가' · '추천' · '높음/낮음' 판정을 붙이지 않는다
- 공급자 화면에 AI 금액을 두지 않는다. 확정 이후 의뢰인 화면에도 두지 않는다
- 속성을 테두리 칩으로 그리지 않는다. 숫자 칸 사이에 칩을 넣지 않는다('불가'는 글자)
- 그림자를 떠 있는 층 밖에 쓰지 않는다
- 열람 기록 띠를 경고색이나 모달로 만들지 않는다
- 로그인 후 화면에 공간 전환 토글을 두지 않는다
- GNB 메뉴를 화면마다 다르게 두지 않는다. 화면 행동 버튼을 GNB에 넣지 않는다
- 본문 · 보조 텍스트를 14 아래로, slate-500보다 연하게 두지 않는다
- 금액에서 '원'과 tabular-nums를 빼지 않는다
- 연락처 · 계정 이메일을 상대 화면에 두지 않는다(가림 토큰으로 대신한다)
- 스테퍼를 가입 흐름 밖에서 쓰지 않는다
- 운영자 화면에 푸터를 두지 않는다

## 13. 열린 항목

| 항목 | 상태 |
|---|---|
| 로고 · 워드마크 | 미착수 — 막대 3개 임시 마크 |
| 일러스트(빈 상태 · 온보딩) | 미착수 — 쓰지 않는 것이 현재 규칙 |
| 다크 모드 | 범위 밖 |
| 모바일 대응 깊이 | 조회 · 간단한 응답(채팅 포함)까지(PRD 7절). 브레이크포인트는 개발 때 정한다 |
| 해소됨 | 되돌릴 수 없는 행동의 버튼 색(→ warn), 출처 '직접 고름'(→ 출처 표시 삭제), 운영자 1:1 문의 답변 화면(→ 11/04 `Admin-Inquiries`, 운영자 셸 + 목록 · 상세 패턴) |
