# 디자인 보완 명세 (11/04) — 빠진 4건 · 확정 뒤 상태 6건 · 푸터 · 디자인 없이 처리할 7건

Claude Code UI 점검(`docs/ui-audit.md`)의 **B. 디자인 자체가 없는 것 11건**을 캔버스 보드와 대조한 결과다. 4건은 이 문서의 명세대로 화면을 더하고, 7건은 기존 화면으로 처리한다. 이어서 연결 작업 중 나온 **B 추가 6건(확인 모달의 확정 버튼 뒤 화면이 없음)**을 Part 1-B로 더했다 — 모두 캔버스에 그려 두었다. 디자인 규격은 디자인 시스템 v0.2.1 최종본, 정책은 PRD v0.7 최종본을 따른다. **스키마 변경은 없다.**

- 상태 이름은 `?mock=<상태>`와 캔버스 Tweak에 그대로 쓴다
- 모달은 기존 계정 설정 모달과 같은 틀: scrim navy 55% · 폭 560~600 · 위에서 120 · 머리(제목 + 한 줄 + ×) / 본문 / 아래(흰 바탕 아닌 slate-50, 오른쪽 정렬 버튼)
- 파란 버튼은 화면당 하나, 위험 확정은 `warn`(amber 테두리), 빨강은 폼 오류에만

### 1-3. 취소 요청 철회 — 의뢰인 계약 취소 요청 (`Cancel-Client`, `/c/contracts/:cid/cancel`)

**어디서** `동의 대기` 상태의 amber 띠 안 [요청 철회](텍스트 버튼, 지금 동작 없음)

**확인 창**(위험 — 파란 버튼 없음, 폭 520)

| 위치 | 내용 |
|---|---|
| 제목 | '취소 요청을 철회할까요?' |
| 본문 16 slate-600 | '계약이 다시 **진행 중**으로 돌아가고, 멈췄던 작업과 검수가 이어집니다. 최준호님에게는 철회됐다고 표시됩니다.' |
| 속성 표기 | `멈춘 기간 │ 11월 8일 ~ 11월 10일 · 3일` / `작업 마감 │ 12월 16일 → 12월 19일` |
| 안내 한 줄 13 | '다시 취소하려면 처음부터 요청해야 합니다.' |
| 버튼 | [닫기](고스트) · **[요청 철회](warn)** |

**철회 후** 내 계약(`/c/contracts`)의 그 계약 카드로 이동, 위 teal 띠 '취소 요청을 철회했습니다 · 계약이 다시 진행 중입니다 · 작업 마감 12월 19일'. 공급자 `Cancel-Supplier`는 회색 대기 띠 대신 '의뢰인이 취소 요청을 철회했습니다 · 계약이 다시 진행 중입니다'(teal 띠) + [내 계약 보기]

| 상태(`?mock=`) | 보드 |
|---|---|
| `요청 철회 확인` | `Cancel-Client` — 동의 대기 화면 위 확인 창 |
| `요청 철회됨` | `Cancel-Supplier` — teal 띠 |
| (철회 후 의뢰인 화면) | `Contracts-Client` `진행 중` + teal 띠 |

**규칙** (철회 시점 · 기한 연장은 11/04 확정 — 결정메모 #19 · #20)
- 철회할 수 있는 때: **상대가 답하기 전(동의 대기)까지만.** 상대가 동의했거나 이의를 냈거나, 3일이 지나 운영자 판정으로 넘어가면 철회할 수 없다(버튼을 보이지 않음)
- 멈춘 기간만큼 **작업 마감과 진행 중인 검수 기한을 늦춘다**(PRD F-26 '요청 중에는 작업 · 검수 · 자동 승인 · 마감 안내가 멈춘다'의 후속)
- 철회는 계약당 취소 요청 1회 제한에서 세지 않는다
- 알림은 보내지 않는다(계약 이후 소식은 '내 계약' 상태로 — PRD F-11)

**데이터** `Contract.status` CANCEL_REQUESTED → ACTIVE, 취소 요청 칼럼(`cancelRequestedAt` · `cancelCause` · `cancelEvidence` 등) 비움, `workDueAt` · 진행 중 `Delivery.inspectionDueAt`에 멈춘 일수 더함. 이벤트는 기존 `CANCEL_RESOLVED`에 `payload.resolution = 'WITHDRAWN'`(enum 추가 없음). API `POST /api/c/contracts/:cid/cancel/withdraw` — `status = CANCEL_REQUESTED AND 상대 응답 없음 AND cancelEscalatedAt IS NULL` 조건부 갱신

## Part 1-B. 확정 버튼 뒤 상태 6건 (추가 점검)

확인 모달은 있는데 확정 버튼을 누른 뒤 보여 줄 화면이 없던 곳. **새 화면은 없고, 기존 보드에 상태를 더했다.** 공통 규칙:

- 확정하면 모달이 닫히고 **같은 화면 위에 teal 띠**(무엇을 했는지 · 시각 · 누가) — 운영자 화면은 띠 안에 '이벤트 기록' 링크
- 처리한 대상은 칩이 바뀐다 — 끝난 것 = 아웃라인(병합됨 · 비활성 · 직접 거절 · 철회함 · 결렬), 상대 · 운영자를 기다리는 것 = 회색(운영자 확인 중 · 다시 납품 기다리는 중), 완료 = teal(단가 수정됨 · 처리 완료)
- 기다리는 동안 누를 것이 없으면 기본 버튼은 `off`로 두고 이름을 '○○ 기다리는 중'으로
- 예시 사유 칸의 '(○○를 고른 경우의 예시)'는 캔버스용 표시 — 구현에서는 빈 칸
