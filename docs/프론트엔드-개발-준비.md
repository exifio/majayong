# 프론트엔드 개발 준비 (11/03 · 11/04 갱신)

화면 설계 캔버스(보드 61개 중 사용 57개 · 폐기 4개)를 기준으로 프론트엔드 개발을 바로 시작할 수 있게 정리했다. 기준은 **화면**이고, 기능 · 규칙은 **PRD v0.7 최종본**, 데이터는 **ERD v0.7 최종본 · schema v0.7 최종본.prisma**(PostgreSQL 실행 검증 70건 통과)를 따른다.

## 0. 확정된 전제

| 항목 | 결정 (11/03 팀 논의) | 개발 영향 |
|---|---|---|
| 공간 전환 토글 | 비로그인 랜딩(의뢰인 랜딩 `/` ↔ 공급자 랜딩 `/supplier`)에만 둔다. 로그인 이후 GNB에는 없다 | GNB는 의뢰인 · 공급자 · 비로그인 헤더 · 운영자 셸 4종, 로그인 이후 GNB에 토글 없음 |
| 계정 · 역할 | 역할은 가입 때 고정(1계정 1역할). 두 역할이 필요하면 다른 이메일로 계정을 따로 만든다 | 로그인하면 역할의 홈으로(`/c` 또는 `/s`), 역할이 다른 공간 경로는 막는다 |

## 1. 링크 점검 결과 (11/03)

- 모든 보드의 모든 상태를 렌더해 링크를 따라가 봤다. **없는 화면으로 가는 링크 0건**, 들어오는 길이 없는 화면 0건, 나가는 길이 없는 화면 0건(폐기 보드 제외).
- 핵심 흐름 연결(가입 → 입력 → 2분할 → 확정 → 모집 → 비교 → 채팅 → 합의 → 서명 → 예치 → 검수 → 정산 → 리뷰 / 공급자 찾기 → 견적 → 지원 → 채팅 → 서명 → 납품 → 정산 / 운영자 메뉴 7개 상호 이동)이 모두 이어진다.
- 이번에 고친 링크: 공급자 프로젝트 찾기 GNB '내 계약'(계약서 → 내 계약), 의뢰인 내 프로필 GNB '홈' · '프로젝트 시작', 견적서 · 단가 리포트 모달 뒤 GNB, 내 프로젝트의 '계약서 확인하기' · '리뷰 쓰기' · '마감 연장하기', 계정 설정 '받은 리뷰'.
- (토글 결정 반영) 로그인 이후 보드 40개에서 공간 전환 토글을 뺐다. 로그인 이후 로고는 역할 홈(`/c` · `/s`)으로, 비로그인 화면의 로고는 의뢰인 랜딩으로 간다.
- GNB 일관성: 의뢰인 22개 · 공급자 18개 보드의 GNB 메뉴 · 채팅 · 알림 아이콘 대상이 모두 같다.
- 캔버스 링크는 화면 단위로만 이동한다. 같은 화면 안의 상태 전환(탭 · 모달 · 제출 결과)은 부록의 동작 목록과 각 보드의 상태(Tweak)로 본다.

## 2. 화면 목록 · 경로(제안)

경로는 제안이다. 역할별 접두어 `/c`(의뢰인) · `/s`(공급자) · `/admin`(운영자). `:pid` 프로젝트, `:aid` 지원(견적), `:tid` 채팅, `:cid` 계약, `:sid`/`:uid` 사용자.

## 3. 상태 모델 (화면에 나온 상태 기준)

| 대상 | 상태 흐름 | 기한 |
|---|---|---|
| 프로젝트 | 작성 중(초안) → 모집 중 → 모집 마감(고르는 중) → 임시 계약 중 → 계약 체결 · 갈래: 지원 0건 마감(마감 연장 · 명세 고치기), 보관 | 모집 기간(데모 7일), 마감 연장 최대 14일 |
| 지원(견적) | 검토 중 → 문의 중 → 선택됨(임시 계약 · 서명 대기) → 계약 · 갈래: 보류, 재견적 요청(명세 수정), 직접 거절, 자동 거절(다른 계약 예치 시), 결렬, 지원 철회 | 견적 질문 최대 3개 |
| 계약 | 서명 대기 → 예치 대기 → 진행 중 → 검수 대기 → 완료 · 갈래: 결렬(서명 거절 · 서명 기한 초과 · 예치 기한 초과 · 임시 계약 취소), 마감 지남, 취소 요청 중 → 동의 → 정산 확정 / 이견 → 운영자 판정 | 서명 7일, 예치 3일, 작업 기간 예치 다음 날부터 |

## 부록 2. 11/04 변경

- **비로그인 랜딩 2종 개편** — 텍스트를 줄이고 이미지 중심으로. 의뢰인: 첫 화면 애니메이션(한 문장 → 화면 초안 → 고치면 총액) → 핵심 가치 카드 3장(서비스 화면 썸네일) → 이용 흐름 5단계 → 안심 포인트 3장 → 마무리(비용은 한 줄). 공급자: 첫 화면 애니메이션(명세 보기 → 가능 · 불가 → 총액 · 기간) → 가치 카드 3장 → 등록부터 정산까지 → 구간 정산 도식 → 마무리. 다른 서비스와의 비교 장면은 넣지 않는다. 애니메이션은 '동작 줄이기' 설정이면 마지막 장면으로 멈춘다
- **고객센터 FAQ 8 → 14개** — 랜딩에서 뺀 설명(예상 총액 계산, 명세 비밀유지, 계약 후 기능 추가, 공급자 선택 기준, 견적 후 작업 증가, 중개자 지위)을 옮겼다
- **운영자 1:1 문의 화면 추가**(`Admin-Inquiries`) — 운영자 사이드 메뉴에 '1:1 문의'(신고 처리 아래) 추가, 운영자 보드 7개 모두 반영. 목록(유형 · 상태 · 경과 시간) + 상세(문의 내용 · 첨부 · 관련 계약 상태 · 답변). 답변을 보내면 인앱 알림(INQUIRY_ANSWERED)과 '내 문의' 표시, 이벤트 기록(SUPPORT_INQUIRY_ANSWERED). 데이터는 기존 SupportInquiry 그대로
- **1:1 문의 화면 분리(`Help-Inquiry`)** — 고객센터는 FAQ · 공지만 두고, '1:1 문의하기'를 누르면 별도 화면으로 간다. 탭 2개: **문의하기**(유형 6 · 관련 계약 · 제목 · 내용 · 첨부 → 문의 보내기) / **내 문의**(목록 + 상세: 문의 내용 · 첨부 · 관련 계약 · 운영팀 답변 또는 '답변을 기다리고 있습니다'). 보내면 '내 문의' 탭으로 바뀌고 방금 보낸 문의가 맨 위(답변 대기). 오른쪽에 '문의 전에 찾아보세요'(FAQ 3개) · 전화 · 이메일. 들어오는 길: 고객센터의 1:1 문의하기 · 내 문의 목록 · 모든 페이지 푸터 '1:1 문의' · 알림 '1:1 문의에 답변이 왔습니다'. 비로그인은 로그인 안내
- **약관 · 정책을 공통 화면으로** — 푸터에서 로그인한 사용자도 들어오므로 보는 사람의 GNB(비로그인 헤더 · 의뢰인 · 공급자)를 쓴다. 비로그인 헤더는 고객센터와 같은 '의뢰인 안내 · 공급자 안내 · 고객센터 / 로그인 · 회원가입'
