## 2. 화면별 상세

### A. 운영자 — 1:1 문의 `Admin-Inquiries` · `/admin/inquiries` (새로)

- 운영자 셸 그대로, 사이드 메뉴 '1:1 문의'(신고 처리 아래, 배지 = 답변 대기 수)
- 머리: 제목 '1:1 문의' + 한 줄 설명 + 세그먼트 탭 '답변 대기 N / 답변 완료 N'
- 왼쪽 목록(360): 유형 거르기 · 찾기, 행 = 유형 칩(중립) · 상태 칩 · 경과 시간(하루 넘으면 amber 600 '하루 지남') / 제목 / 보낸 사람 · 관련 계약 유무
- 오른쪽 상세: 유형 · 상태 칩 → 제목 → 보낸 사람 · 접수 시각 · 이전 문의 수 → 문의 내용 · 첨부 → **관련 계약 4칸**(계약 상태 · 예치 금액 · 결제사 통지 · 결제 카드 끝자리) + '이벤트 기록에서 보기' → 답변(필수, 자주 쓰는 문구 칩 3개) → 안내 한 줄 + **'답변 보내기'(이 화면의 유일한 파란 버튼, 비어 있으면 비활성 + 이유 한 줄)**
- 보낸 뒤: teal 띠 '답변을 보냈습니다 · 시각 · 운영자' + 상세의 답변 칸이 '보낸 답변'(teal 테두리)으로
- 상태(`?mock=`): 답변 대기 / 답변 작성 / 답변 보냄 / 답변 완료 탭
- 데이터: `SupportInquiry`(status WAITING → ANSWERED, answer · answeredById · answeredAt), API `GET /api/admin/inquiries?status=` · `GET /:id` · `POST /:id/answer`, 알림 `INQUIRY_ANSWERED`, 이벤트 `SUPPORT_INQUIRY_ANSWERED`. 개인정보는 끝자리만

### B. 공통 — 1:1 문의 `Help-Inquiry` · `/help/inquiry` (새로)

- 셸 viewer(보는 사람의 GNB) · 가드 none. 비로그인은 본문에 로그인 안내 상자(회원가입 · 로그인)만
- API는 세션 역할로 고른다 — 의뢰인 `/api/c/inquiries`, 공급자 `/api/s/inquiries`(목록 · 상세 · 작성). 관련 계약 선택지는 자기 계약만
- 머리(흰 바탕): 이동 경로 '고객센터 › 1:1 문의' → 제목 → 한 줄 → **밑줄 탭 '문의하기' / '내 문의 N'**(`?tab=my`)
- 문의하기: 문의 유형 6(선택 카드) · 관련 계약(선택) · 제목 · 내용 · 파일 올리기(3개 · 10MB) · 안내 한 줄 · '취소'(→ `/help`) + **'문의 보내기'**
- 내 문의: 목록(상태 칩 · 유형 · 제목 · 날짜, 선택 행 blue-50 + 왼쪽 막대) + 상세 카드(유형 · 상태 → 제목 → 접수 시각 · 관련 계약 링크 → 문의 내용 · 첨부 → 답변: teal 상자 '마자용 운영팀 · 시각' + '추가로 문의하기' / 대기면 회색 상자 '답변을 기다리고 있습니다')
- 보낸 뒤: '내 문의' 탭으로, teal 띠 '문의를 보냈습니다', 방금 보낸 문의가 맨 위(답변 대기) · 상세가 열린 채
- 오른쪽 칼럼: '문의 전에 찾아보세요'(역할별 FAQ 3개 → `/help`) · 전화 · 이메일 · '이런 일은 문의 대신'(계약 취소 요청 · 신고)
- 상태(`?mock=`): 문의 작성 / 문의 보냄 / 내 문의 — 각각 의뢰인 · 공급자 · 비로그인(보드 Tweak '누가'는 DEV 세션 패널로 바꾼다)

### C. 공통 — 고객센터 `Help` · `/help`

### E. 비로그인 랜딩 2종 `Main` · `Supplier-Landing`

공통 — 섹션마다 제목 1줄 + 설명 1줄, 그림은 서비스 화면을 축소한 것. 다른 서비스와 비교하는 장면 없음. 섹션 바탕은 흰색 / slate-50 번갈아.

| 의뢰인 랜딩 `/` | 공급자 랜딩 `/supplier` |
|---|---|
| ① 첫 화면 — 제목 그대로, 설명 1줄, 오른쪽 **3장면 애니메이션**: 한 문장 입력(타이핑) → 화면 초안(블록 차례로) → '노쇼 기록' 지우면 예상 총액 512만원 → 441만원, 문구 amber '예산보다 12만원 많아요' → teal '예산 안에 들어옵니다'. 아래 단계 알약 3개 | ① 첫 화면 — 설명 1줄, 오른쪽 **3장면 애니메이션**: 프로젝트 상세(명세 4줄) → '노쇼 기록' 가능 → 불가 → 총액 3,000,000원 · 42일 · 예상 수령액 2,850,000원 + teal '견적을 보냈습니다' |
| ② **외주 맡기기가 쉬워집니다** — 가치 카드 3장(위: 서비스 화면 썸네일 / 아래: 제목 + 한 줄): 기능을 몰라도 시작 · 예산 안에 드는지 바로(총액만, 기능별 금액 없음) · 같은 명세로 견적 비교 | ② **견적이 쉬워집니다** — 가치 카드 3장: 기능이 이미 정리됨(명세 항목) · 총액으로 제안(총액 · 기간 입력) · 계약 후 범위가 늘지 않음(계약서 · 양쪽 서명) |
| ③ **명세를 확정한 다음은** `#how` — 흐름도 5단계: 명세 확정 → 견적 받기 → 조건 정하기 → 계약 · 예치 → 검수 후 지급 | ③ **등록부터 정산까지** `#flow` — 흐름도 5단계: 프로필 등록 → 명세 고르기 → 견적 보내기 → 채팅 · 서명 → 구간 정산 |
| ④ **안심하고 맡길 수 있도록** `#safe` — 아이콘 카드 3장: 돈은 마자용이 맡아 둡니다 · 계약한 범위는 바뀌지 않습니다 · 명세를 본 사람이 기록됩니다 | ④ **대금은 나눠서 받습니다** `#price` — 상자 3개(전액 예치 → 중간 검수 승인 · 1차 지급 → 최종 검수 승인 · 2차 지급), 금액 없음 + '의뢰인이 7일 안에 답하지 않으면 자동으로 승인됩니다' |
| ⑤ 마무리 navy 띠 `#start` — 버튼 아래 '명세까지 무료 · 계약이 성사될 때만 수수료 5%' | ⑤ 마무리 navy 띠 — '가입 · 견적 · 채팅 무료 · 지급될 때만 수수료 5%' |

- 랜딩 안 메뉴: 의뢰인 작동 방식 `#how` · 안전장치 `#safe` · 비용 `#start` / 공급자 **견적 방식 `#how` · 이용 흐름 `#flow` · 정산 · 비용 `#price`**
- 애니메이션: CSS keyframes 9초 반복. **`prefers-reduced-motion: reduce`면 마지막 장면을 정지 화면으로.** 장면 그림 안 초안은 slate만(2계층 규칙)
- 상태(`?mock=`): 자동 재생 / 장면 1 / 장면 2 / 장면 3 — 장면 고정은 애니메이션을 끄고 그 장면만
