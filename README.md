# 마자용

처음 외주를 맡기는 사람이 **화면 초안을 고치면서 원하는 기능과 예산을 정리**하는 서비스입니다.

> 문서 묶음 v1.4 · 2026-10-27  
> 제품 기준은 기존 PRD v0.6입니다. 이번 수정은 문서 표현을 바꾼 것이며, 기능이나 담당 범위를 바꾼 것은 아닙니다.

## 서비스는 어떻게 사용하나요?

의뢰인이 필요한 일을 한 문장으로 설명하거나 기본 초안을 고릅니다. 화면에서 기능을 추가·삭제하면 기능 목록과 예상 금액도 함께 바뀝니다.

기능 목록을 확정하면 프로젝트가 등록됩니다. 공급자가 기능별 견적을 보내고, 의뢰인은 한 명을 선택합니다.

이후 **계약 → 테스트 결제 → 납품·검수 → 정산 기록 → 상호 리뷰**로 이어집니다.

첫 버전은 **예약기반음식점**을 대상으로 합니다. 결제는 실제 돈이 오가지 않는 **테스트 환경(sandbox)**만 사용합니다.

## 지금은 어디까지 진행됐나요?

현재 `back_a` 기준 **M0(서버·DB·안전 제약·공통 기반) 및 M1(F-04 공급자 단가·절사평균 예상 금액)** 기본 구현과 로컬 PostgreSQL 검증까지 확인되었습니다.

전체 계획은 **개발 시작일부터 22일**입니다. M0~M6는 단계 이름이며, 실제 시작일과 마감일은 아직 정해진 것으로 보지 않습니다.

## 누가 무엇을 맡나요?

| 담당 | 맡은 일 |
|---|---|
| **Agent A** | 서버·DB, 예상 금액, 프로젝트 탐색, 견적·수락, 알림·북마크·추천 |
| **Agent B** | 계약, 테스트 결제, 납품·검수, 정산·환불 상태, 리뷰 |
| **다른 팀원** | 로그인·프로필, AI 분류·화면 초안, 프로젝트 등록·명세 수정, 화면 개발 |

A와 B는 동시에 작업합니다. B는 A의 견적 기능이 완성되기 전에도 **수락된 지원서 예시 데이터**로 계약·금액 계산을 시험할 수 있습니다.

## 어떤 문서를 보면 되나요?

| 알고 싶은 내용 | 볼 문서 |
|---|---|
| A가 지금 하는 일 | `docs/TASKS_A.md` |
| B가 지금 하는 일 | `docs/TASKS_B.md` |
| 전체 개발 순서와 서로 연결할 시점 | `docs/PLAN.md` |
| 어떤 기능을 만들고, 언제 완료로 볼지 | `docs/PRD.md` |
| 데이터·금액·화면을 어떻게 처리할지 | `docs/DESIGN.md` |
| 에이전트가 지켜야 할 작업 규칙 | `AGENTS.md` |

평소에는 두 TASKS 파일의 **지금 할 일 / 다음 작업 / 완료한 일 / 협의할 일**을 확인하면 됩니다. 자세한 조건이 궁금할 때 PRD와 DESIGN을 확인합니다.

## 에이전트에게 작업을 맡기는 방법

1. A와 B를 **서로 다른 작업 폴더**에서 실행합니다. Git worktree는 같은 저장소를 별도 폴더에서 작업하는 방식입니다.
2. 각 에이전트에게 `AGENTS.md`와 자신의 TASKS 파일을 읽고, 관련 PRD·DESIGN·PLAN을 확인하도록 지시합니다.
3. A는 `TASKS_A.md`만, B는 `TASKS_B.md`만 갱신합니다. 완료 표시는 실제 코드와 테스트 결과를 확인한 뒤 합니다.

**문서는 자동으로 공유되지 않습니다.** 각 작업 폴더에 처음 한 번 복사해야 합니다. 이후 A의 최신 현황은 A 폴더에서, B의 최신 현황은 B 폴더에서 확인합니다. 공통 결정이 바뀌면 두 폴더에 모두 반영해야 합니다.

## Git에는 무엇을 올리나요?

**올리지 않는 것:** 루트 `AGENTS.md`, `docs/` 전체, `.env`와 실제 비밀 키.  
**올릴 수 있는 것:** `README.md`, `.gitignore`, 프로그램 코드. `.env.example`에는 실제 키 값 없이 변수 이름만 둡니다.

기존 `.gitignore`는 덮어쓰지 말고 필요한 규칙만 추가합니다. 이미 Git이 추적하는 문서는 별도로 추적을 해제해야 합니다. 절차는 `AGENTS.md`에 있습니다.

이 문서 묶음에는 **Markdown 문서 7개와 `.gitignore`**가 들어 있습니다. 실제 소스 코드나 DB를 새로 만든 묶음은 아닙니다.

## 언제 완료로 보나요?

배포된 서비스에서 **초안 → 프로젝트 등록 → 견적·수락 → 계약 → 테스트 결제 → 검수·정산 → 리뷰**까지 실제로 이어져야 합니다. 과제 제출용 ERD, API 명세서, 발표 자료도 별도로 준비합니다.

## 확인된 백엔드 실행 환경과 명령어

- 런타임·패키지: Node.js `v26.9.0`, TypeScript `^7.0.2`, Express `^5.1.0`, Prisma / `@prisma/client` `^6.19.3`, PostgreSQL
- 환경 변수: `.env.example`을 복사해 `.env`에 `DATABASE_URL` 등을 설정합니다.
- 주요 명령어:
  - 스키마 검증·클라이언트 생성: `npm run db:validate && npm run db:generate`
  - DB 마이그레이션 적용: `npm run db:migrate`
  - 개발 서버 실행: `npm run dev` (API 문서: `http://localhost:3000/api-docs`)
  - 타입 검사 및 빌드: `npm run typecheck && npm run build`
  - 통합 테스트 실행: `npm test`
